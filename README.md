# docfactory — фабрика MCP-серверів документації

Один рушій, багато ізольованих серверів. Кожен сервер відповідає на питання про свій звід документації — сьогодні
ECMAScript, завтра Vue, потім Go чи .NET — через MCP: пошук по корпусу плюс чотири шари захисту з модуля 6. Домени
не змішуються: спільний тут лише код, усе інше в кожного своє.

Це мультиорендна побудова. Кожен домен — окремий примірник (орендар), і між примірниками немає нічого спільного,
крім рушія й шаблону сервера та одного контейнера Qdrant. Купа не збирається, бо жодні дані не глобальні: команда
завжди дістає імʼя примірника й чіпає лише його.

## Навіщо це — прилад проти впевненої вигадки

Це не «пошук по документації», хоч зовні схоже. Модель, яка не знає меж того, що їй дали, не мовчить — вона
вигадує: на питання про розділ, якого в неї немає, вона називає номер сусіднього з тією самою впевненістю. Усе тут
зроблено так, щоб таку відповідь було важко вимовити:

- у корпусі лише нормативні документи — сама специфікація і стандарти, на які вона спирається; ані підручників,
  ані статей, ані коментарів з інтернету;
- одиниця відповіді — клауза з номером розділу, назвою документа й адресою джерела, тож кожну цитату можна
  перевірити за хвилину;
- описи інструментів довгі навмисно: вони кажуть моделі, коли інструмент кликати **не треба** (браузери, DOM,
  Node, TypeScript — цього тут немає, і пошук повернув би «чужі розділи з переконливими номерами»), велять писати
  запит ідентифікаторами самої специфікації і складати відповідь «з кроків, що повернулися, а не з пам'яті»;
- другий із чотирьох шарів захисту відхиляє `read_section` на ідентифікатор, якого пошук не показував, —
  вигаданий id не має шляху стати «текстом стандарту».

Звідси три застосування. Розробка строго за специфікацією: асистент, що пише код, цитує клаузу, а не пригадує
статтю з блогу, і ревʼю закриває суперечку одним посиланням. Підготовка до співбесіди: те саме питання від людини —
що стандарт насправді каже про `Object.prototype.toString`, про приведення типів, про протокол ітерації — з
відповіддю, що несе номер розділу. Ревʼю коду проти стандарту: рецензент, здатний процитувати 20.1.3.6, закриває
суперечку, яку думкою не закрити.

І одна межа, яку варто назвати: корпус відповідає, чого стандарт **вимагає**, а не що браузери **роблять**. Клауза
може бути нормативною роками, перш ніж два рушії на ній зійдуться. Це не вада — це кордон інструмента, і саме тому
кожен розділ, що випав з індексу, коштує більше за свій розмір: він породжує не мовчання, а номер сусіднього
розділу, сказаний з тією самою впевненістю.

## Що ізольовано на домен

- свій порт і свій запис у Claude Code (сервер піднятий постійно, Claude Code під'єднується за URL);
- своя колекція у спільному Qdrant — `docs-<домен>`;
- своя тека документів `corpus/`;
- свій `sources.json` — звідки той корпус будується;
- свій конфіг — назва, колекція, порт, модель векторів;
- свій власний захищений агент (Mode A) з усіма чотирма шарами.

Спільне — тільки `engine/` (як будувати корпус) і `server/` (як його віддавати). Другий домен нічого в них не
міняє: він додає свій `instances/<домен>/` і, за потреби, нового читача.

## Розкладка

```
docfactory/
  engine/          спільне: схема sources, білий список, реєстр читачів, збірка corpus, заливка у вектор
    readers/       toc  page  rfc  report  ldml  pdf   (+ markdown  html  sitemap … з новими доменами)
  server/          спільний MCP-сервер (HTTP) + чотири шари + власний агент; параметр — конфіг примірника
  instances/
    ecmascript/    sources.json   corpus/   config      ← перший примірник, з нинішнього final
    vue/           sources.json   corpus/   config
    go/  …
  new              фабрика: створити порожній примірник
```

## `sources.json` — сховище лінків і водночас білий список

Один запис на джерело (ендпоінт). Поля:

- `id` — стабільний ключ (`ecma262`, `ecma402`, `rfc4647`, `uts35-3-numbers`…);
- `url` — адреса;
- `reader` — як читати відповідь: `toc`, `page`, `rfc`, `report`, `ldml`, `pdf` (для нового домену — новий читач);
- `title` — людська назва;
- `added` — дата, коли додали;
- `note` — навіщо це джерело в корпусі (замість коментарів у коді);
- `expand: chapters` — для `toc`, щоб багатосторінкове видання лишалось динамічним по главах.

Цей файл не лише каже, звідки качати, а й обмежує оновлювач: тягнути можна тільки те, що тут задекларовано, і
нічого іншого. Дозволені адреси виводяться з `url` усіх записів (для `toc` — ще й дочірні тієї самої адреси); усе
поза цим переліком відхиляється. Якщо якась інструкція — хоч би й з отруєного документа — скаже «скачай звідси» на
незадеклароване джерело, оновлювач відмовляє. Це та сама логіка модуля 6, опущена на шар завантаження.

Керування — редагуванням файла: додав запис — джерело зʼявилось, прибрав — зникло, змінив `url` — наступне
оновлення тягне з нового місця. Команди: `./df <домен> sources` (перелік), `./df <домен> sources --why` (друкує
`note`), `./df <домен> refresh [id]` (тягне все або одне джерело в `corpus/`).

## Життєвий цикл примірника

```
./df new go                     # (ще немає, фаза 5) створити instances/go/: sources.json, config (docs-go, вільний порт)
# заповнити instances/go/sources.json джерелами документації Go
./df go refresh                 # завантажити corpus за sources.json (лише задеклароване)
./df go vectors                 # залити corpus у колекцію docs-go
./df go serve                   # підняти HTTP-сервер на своєму порту
# додати запис-URL у .mcp.json — Claude Code бачить сервер go
```

Кроки однакові для будь-якого домену. Відрізняються тільки `sources.json` і, зрідка, набір читачів.

## Як підняти примірник

Загальна частина однакова для всіх доменів, а що в кожного своє — нижче, у переліку примірників. Усе біжить із bash
(Linux, macOS або WSL на Windows) із кореня `docfactory/` через `./df <домен> <крок>`. Venv у кожного примірника
свій і лінуксовий (`.venv/bin/python`), тож із нативного Windows-шелу `df` не запускається.

Передумови: Python 3.10 або новіший; Docker — лише для пошуку за змістом, і він необов'язковий; ключ Anthropic —
лише для повного прогону агента. Рукостискання, сервер під Claude Code і пошук працюють і без ключа, і без Docker.

Спершу venv примірника — один раз, з його теки. Це єдиний крок, що робиться зсередини `instances/<домен>/`;
активувати venv не треба ані зараз, ані потім — `df` сам викликає `.venv/bin/python` потрібного примірника:

```
cd instances/<домен>
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env            # впишіть ANTHROPIC_API_KEY, якщо потрібен крок ask
cd ../..                        # назад у корінь: усі кроки df запускаються тільки звідти
```

Далі все з кореня `docfactory/` — з теки примірника `./df` не знайдеться. Гроші витрачає рівно один крок —
`ask`, власний агент проєкту: лише він говорить із моделлю Anthropic, і лише йому потрібен ключ. Сервер із
моделлю не розмовляє взагалі: коли клієнт — Claude Code, моделлю є сам Claude Code, він кличе два інструменти й
платить своїми токенами з підписки, яка вже є. Без `.env` усе інше працює, а `ask` зупиняється до будь-якого
мережевого виклику з підказкою, чого бракує.

| Крок | Що робить | Мережа | Коштує |
|------|-----------|:------:|--------|
| `sources [--why]` | перелік джерел і білий список | ні | $0 |
| `list` | що завантажилося б, без запису | так¹ | $0 |
| `check [--deep]` | чи змінилося щось нагорі за джерелом | так¹ | $0 |
| `refresh [id…]` | завантажити корпус, лише задеклароване | так¹ | $0 |
| `manifest` | оновити паспорт `corpus/index.json` | ні | $0 |
| `setup` | спитати раз: Qdrant чи пошук по словах | ні | $0 |
| `vectors [--refill]` | залити корпус у Qdrant — пошук за змістом | Docker локально | $0, хвилини CPU |
| `serve` | HTTP-сервер MCP на порту примірника; окремий термінал, лишити жити | ні | $0 |
| `status` | стан бази й розклад оновлення | ні | $0 |
| `smoke` | перевірки сервера повз протокол | ні | $0 |
| `protocol` | діалог по протоколу, чужим клієнтом | ні | $0 |
| `quality` | замір: що дає пошук за змістом | ні | $0 |
| `raw` | сирі кадри JSON-RPC, без бібліотеки | ні | $0 |
| `tools` | MCP-рукостискання: має показати `search_spec` і `read_section` | ні | $0 |
| `ask "питання"` | повний прогін власного агента з усіма чотирма шарами | Anthropic | **платно** — токени моделі, потрібен ключ |

¹ Лише задекларовані в `sources.json` адреси — білий список.

Підйом сервера і під'єднання Claude Code — окремий розділ нижче: «Як підняти локальний MCP-сервер».

Пошук за змістом без Docker не працює, і це не біда: типово сервер шукає по словах, і цього досить. `vectors`
підніме контейнер `agent0826-qdrant`, довантажить модель векторів і кілька хвилин рахуватиме їх — один раз, далі
лише зміни. Питання «піднімати чи ні» ставиться один раз: перший `serve` у живому терміналі спитає сам, поки
рішення ще не записане у `out/mode.json`; `setup` ставить те саме питання будь-коли ще раз, а відповідь можна
передумати в обидва боки.

## Як підняти локальний MCP-сервер

Сервер під Claude Code — окремий процес: його тримають запущеним, а Claude Code під'єднується до нього за
адресою. Звідси й порядок: спершу сервер, потім запис у клієнті, потім перевірка.

**1. Підняти сервер** — окремий термінал, з кореня `docfactory/`, і лишити його жити (приклад для примірника
`ecmascript`: `./df ecmascript serve`):

```
./df <домен> serve
```

Порт береться з `config.json` примірника (у ecmascript — `8760`, адреса `http://127.0.0.1:8760/mcp`). Від запуску
до першої відповіді — близько 5 секунд: стільки збирається індекс по словах. Найперший `serve` у живому терміналі
може спитати, чи піднімати Qdrant; відповідь `n` безпечна — нічого не встановлюється, сервер шукає по словах.

**2. Додати сервер у Claude Code** — одним із двох способів:

- відкрити теку `instances/<домен>/` як проєкт у Claude Code: він побачить `.mcp.json` цієї теки й запропонує
  сервер, який треба підтвердити;
- або командою: `claude mcp add --transport http <назва> http://127.0.0.1:<порт>/mcp` (приклад для
  `ecmascript`: `claude mcp add --transport http ecma-spec http://127.0.0.1:8760/mcp`).

Це робиться один раз — запис лишається, і надалі досить самого кроку 1.

**3. Перевірити під'єднання.** У сесії Claude Code — команда `/mcp`: має бути сервер і два інструменти,
`search_spec` та `read_section`. Поза сесією той самий перелік дає `claude mcp list`.

**4. Якщо «failed / not connected».** Майже завжди сервер не піднятий (крок 1) або порт інший — звірте адресу з
полем `port` у `config.json` примірника. Після підйому сервера Claude Code перепід'єднається сам: ані запис у
`.mcp.json`, ані сесію перезапускати не треба.

## Оновлення корпусу

Корпус — це тека `instances/<домен>/corpus/`: локальна копія документації звичайними текстовими файлами.
Завантажена вона з офіційних сайтів, перелічених у `sources.json` примірника (для ecmascript це tc39.es,
ecma-international.org, unicode.org і rfc-editor.org). Оригінали на тих сайтах змінюються, а наша копія сама про
це не дізнається — оновлення запускають руками, п'ять кроків по одній команді:

1. **Звірка** — `./df <домен> check`. Сходить на кожну адресу з `sources.json` і порівняє оригінал з нашою
   копією. Лише друкує різницю — «новий», «змінився», «зник» — і нічого не завантажує й не змінює.
2. **Завантаження** — `./df <домен> refresh <що саме>`. Тягне з тих самих адрес свіжі версії названих документів
   і перезаписує їх у `corpus/`; без імен — перезавантажує весь корпус.
3. **Паспорт** — `./df <домен> manifest`. Паспорт — це файл `corpus/index.json`, опис нашої копії: для кожного
   документа адреса, дата завантаження і контрольна сума тексту. Саме за цими сумами звірка відрізняє
   «змінилося» від «те саме», тож після завантаження паспорт перегенеровують — інакше наступний `check`
   показуватиме вже завантажене як нову зміну.
4. **Вектори** — `./df <домен> vectors`, і лише якщо примірнику ввімкнено пошук за змістом (той, що через
   Qdrant). Такий пошук тримає кожен фрагмент тексту в базі числовим відбитком — вектором; текст змінився —
   відбиток треба порахувати наново. Команда сама бачить, що змінилося, і рахує лише його. З типовим пошуком по
   словах цього кроку просто немає.
5. **Перезапуск** — Ctrl+C у терміналі, де живе `serve`, і знову `./df <домен> serve`. Сервер читає `corpus/`
   один раз, при старті, тож свіжу копію він побачить лише після перезапуску.

Той самий шлях у подробицях — що скільки триває, з Qdrant і без нього, особливі випадки на кшталт зсуву глав —
в окремому довіднику: [UPDATE.md](UPDATE.md).

## Примірники

### ecmascript

Специфікація ECMAScript: ECMA-262 плюс ECMA-402, 404, 414 і вільні документи, на які спирається 402.

- порт `8760`; запис у Claude Code — `ecma-spec`, адреса `http://127.0.0.1:8760/mcp`;
- колекція у Qdrant — `docs-ecmascript`, модель векторів — `bge-small`;
- корпус уже лежить у `instances/ecmascript/corpus/` — для старту `refresh` не потрібен, лише для оновлення;
- ключ — в `instances/ecmascript/.env`, зразок — `.env.example` поруч;
- приклад питання агентові: `./df ecmascript ask "How does Object.prototype.toString build the tag?"` — індекс
  англійський, тож і питання англійськими термінами специфікації, а відповідь — мовою питання;
- докладніше, разом із межами захисту, — у [instances/ecmascript/README.md](instances/ecmascript/README.md).

## Захист

- Серверний санітар видачі — розтяжка на очевидні формулювання вшитих указівок, не класифікатор: зачеплений
  фрагмент вилучається з відповіді цілком, зі спрацюванням у журналі; вказівку, сказану іншими словами, вона не
  впізнає.
- Вузький перелік інструментів — сервер віддає лише `search_spec` і `read_section`.
- Білий список джерел — оновлювач тягне тільки задеклароване (див. вище).
- Власний агент (Mode A) — усі чотири клієнтські шари; під'єднується до порту свого примірника. Коли клієнт —
  Claude Code, ці чотири шари вже на його боці, а на сервері лишаються перші три пункти.

## Читачі

Читач — це обробник одного формату джерела: дістає відповідь, віддає чистий текст документа. Домен ECMAScript
приносить шість: `toc` (багатосторінкове видання, глави динамічно), `page` (одна сторінка ecmarkup), `rfc`,
`report` (звіти Unicode з номерами розділів), `ldml` (частини UTS #35), `pdf`. Новий домен додає своїх
(`markdown`, `html`, `sitemap`…) і кладе свій `sources.json`; рушій не чіпається.

## Стан і дорожня карта

Примірник `ecmascript` уже живе в `instances/ecmascript/` (переїхав із `final/`) і містить самі дані домену:
корпус, `sources.json`, `config.json`, `.env`, `.mcp.json`. Увесь код спільний — `engine/` (як будувати корпус),
`server/` (MCP-сервер, чотири шари, власний агент), `common/` (пошук по словах і за змістом). Пошук іде і по словах
(BM25), і за змістом (fastembed + Qdrant); сервер відповідає і на stdio, і на HTTP. Лишилося тільки scaffold нових
доменів.
